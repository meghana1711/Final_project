Installing LSF Web Services for a high availability environment
High availability (HA) for LSF Web Services involves installing multiple instances of LSF Web Services on LSF servers or management hosts. A
gateway provides a single URL for users to access LSF Web Services and balances the load among the instances. After you have installed your
instances of LSF Web Services, you then conﬁgure a load balancer that meets your business needs, such as Apache HTTP Server, HA Proxy, or
NGINX. The following information illustrates how to conﬁgure Apache HTTP Server as a load balancer for LSF Web Services with HA: either as your
HTTP proxy or HTTPS proxy for LSF Web Services. Instead of Apache HTTP Server, you can use a different load balancer, and use this information as
a guide to conﬁgure your load balancer for your HA environment. Moreover, the steps illustrate conﬁguring the Apache HTTP Server without
redundancy in load balancer itself; however, a common approach with HA is to run multiple load balancers in an active-passive deployment (for
example, you can use Keepalived so that multiple daemons run on different hosts and read from a common IP address, but only one of these is
active at any point in time). Consider the best option for your HA environment as you use the guidance provided here.
Before you begin
Tip: If you are not using a failover environment for LSF Web Services, then you do not have to install multiple instances of LSF Web Services. Refer to
the installation steps in Installing LSF Web Services instead.
Before installing multiple instances of LSF Web Services and enabling high availability, note these prerequisite criteria:
If you want to use LSF Web Services in a high availability environment, you must enable high availability during the LSF Web Services
installation. If you want to use high availability after your installation, uninstall and reinstall your LSF Web Services instances.
Select at least two hosts on which to install LSF Web Services. The hosts must:
Have access to the LSF environment.
Be LSF management or LSF server hosts with the appropriate system requirements.
Have clocks set to the same time as the LSF management host. The times must be synchronized.
Select a separate host to install Apache HTTP Server 2.4.37 or later. Ensure that this remote server is accessible from each host in your high
availability environment.
You require conﬁguring a shared ﬁle system for the hosts for your high availability environment. The shared disk is used to store conﬁguration
ﬁles and the work directory. On this shared ﬁle system:
Ensure a uniform access path from each host.
Ensure that the root user has permission to the shared ﬁle system.
You require root privileges to install LSF Web Services.
The path to the home directory set in the repository of the LSF Web Services environment must use NFS sharing or a NAS, SAN, or Cloud
storage sharing directory.
Download the LSF Web Services installation package from the same site where you downloaded Fix Pack 15: IBM Fix Central. Select the
operating system type that matches your LSF installation (Linux ARM, Linux on POWER LE, or Linux x64). Once you have the installation
package downloaded, you can install it. Download to your shared ﬁle system.
