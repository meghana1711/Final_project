Required components
In addition to an LSF cluster, including a management host and execution hosts, LSF Data Manager requires the following components, which must
all be accessible to the cluster:
A staging area, which is a shared directory that stores ﬁles that are to be staged in or out
An LSF data manager host
At least one data transfer node (I/O node), which is an LSF server host that is mounted with direct access to the cluster staging area
LSF data manager administrators
LSF data manager administrators must be administrators in each of the connected LSF clusters. The ADMINS parameter in the lsf.datamanager ﬁle
lists the LSF administrators who can reconﬁgure and shut down the LSF data manager daemon (dmd). LSF data manager administrators can use the
bdata tags command to list or clean intermediate ﬁles that are associated with a tag for users.
You cannot conﬁgure the root user as an LSF data manager administrator, but root has the same privileges as an LSF data manager administrator.
Staging area requirements
The following are requirements for the staging area:
Any compute node in the cluster that does not directly mount the staging area must conﬁgure passwordless SSH access to the staging area
ﬁle servers.
Each data manager must manage a single staging area.
Host requirements
Select at least one LSF server host as the data manager host.
The following are requirements for the data manager host:
LSF data manager must be able to write to the staging area ﬁle system as root.
If failover is required for the data manager, conﬁgure multiple data manager candidate hosts. All candidates must mount the staging area at
the same local path.
Important: Use LSF server hosts as data manager hosts. LSF automatically starts dmd, and monitors it for failover.
Data transfer node requirements
Each node must have read/write access to the mounted staging area.
For input data requirements (data stage in), data transfer nodes must be able to reach the data source location through the conﬁgured transfer
tool.
For output data requirements (data stage out), data transfer nodes must be able to reach the data destination location through the conﬁgured
transfer tool.

These nodes must statically mount the staging area at the same location as the LSF data manager host.
These nodes must be conﬁgured as LSF execution hosts in the data transfer queue.
Data transfer nodes are execution hosts for transfer job that LSF data manager submits to a data transfer queue, which has the
DATA_TRANSFER=Y parameter speciﬁed. Specify the LSF server hosts in the HOSTS parameter in the lsb.queues ﬁle for the data transfer
queue.
The data transfer tool is the command that is speciﬁed in the FILE_TRANSFER_CMD parameter in the lsf.datamanager ﬁle. LSF data manager uses
the data transfer tool to transfer data ﬁles. The speciﬁed tool runs on the data transfer node.
The data transfer tool must be able to move (stage in) data from the data source host to the staging area. The data transfer tool must also be able to
move data from the staging area to the data destination host (stage out).
By default, the scp command is data transfer tool.
Note:
Make sure that passwordless SSH is conﬁgured from the data transfer nodes and submission hosts to the data source and destination hosts.

About this task

Conﬁgure the following parameters to use data manager features:
Procedure
1. Conﬁgure the following parameters in the lsf.conf ﬁle:
LSF_DATA_HOSTS
Specify a space-separated list of host names for the data manager hosts that are associated with this cluster.
This parameter must be deﬁned in every cluster that uses the data manager. Deﬁning this parameter acts as a switch, activating the
data manager features. All candidate data managers must agree on the value of this parameter (host names and order).
LSF_DATA_PORT
Specify the port number of the data manager daemon that is associated with this cluster. The default value is 1729.
2. Conﬁgure the following parameters in the lsf.datamanager ﬁle:
ADMINS
Deﬁne the data manager administrators.
Note: The speciﬁed LSF data manager administrators must also be LSF administrators in the connected LSF cluster.
STAGING_AREA
Specify the path to the top of the staging area as it is accessed from the data manager hosts.
Any host on which the data manager runs must statically mount the staging area. If no host name is speciﬁed, it is assumed that all
hosts that mount the staging area do so at the same path. If a host name is speciﬁed, then the speciﬁed host name and path must be a
subdirectory of an exported ﬁle system.
3. Conﬁgure a data transfer queue in the lsb.queues ﬁle.
Begin Queue 
QUEUE_NAME = transfer 
DATA_TRANSFER = Y 
HOSTS=xfernodeA xfernodeB xfernodeC 
End Queue
