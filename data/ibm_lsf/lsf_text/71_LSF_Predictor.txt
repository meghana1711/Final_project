Known issues
Jobs remain in Pending state

Experiment result not accurate if system decides time compression factor
When starting a simulation in the LSF cluster, which has LSF License Scheduler enabled, select Specify Factor for the Time Compression

Limitations
Supported delimiter set
You can use the following data delimiters to ﬁnd job names, project names, job directories, and more:delimitCharSet = ['#', '-', 
'_', '%', '+', '@', '/', '!', ' ', '.', ':']
Job names
The new job feature name is abstracted from the project name and the job name cannot consist of numerical values. If the abstracted features
name values are numerical for all jobs in the training data, AutoAI converts it to a Number type and model inference will fail. All of the
customized new features are expected as a String type.
Dynamic hosts are not supported
Dynamic hosts are not recognized: If the LSF cluster to be simulated contains dynamic hosts, the simulator data collecting tool tries to convert
those dynamic hosts to static in the collected data so that they show up as static hosts in the simulated cluster. The conversion adds those
hosts to the lsf.cluster.<cluster_name> ﬁle in the conf directory in the collected data and add the dynamic hosts into the hostlist line. This
adds the hosts as static hosts and be recognized by the simulator.
LSF Data Manager leads to improper results
If LSF Data Manager is enabled in LSF production environment, the experiments will count 1024 CPUs for the data manager master host,
which leads to improper results. Suggest to disable the LSF Data Manager before loading the LSF conﬁguration into the LSF Cognitive system.
Dynamic resources converted to ﬁxed resources
Dynamic resources reported from elim are converted to ﬁxed resources when loading LSF conﬁguration.
Predictor does not support multicluster mode
LSF Predictor 10.1 only works with a single LSF cluster. Predictor doesn't support LSF multi-cluster mode.
Fair share user groups not imported with workload snapshot
User groups deﬁned in queue level as fairshare are not imported when you import a workload snapshot. User groups deﬁned in bsub -G
are imported properly.

About this task
The following list contains the basic concepts associated with the Predictor service:
Experiment
An experiment is an LSF simulation run that uses a selected LSF conﬁguration and workload snapshot.
Cluster conﬁguration
An LSF conﬁguration is a full set of LSF cluster conﬁgurations and workload policies.
Workload snapshot
A workload snapshot is a set of job submissions and completion records that are imported from the LSF cluster events ﬁles (lsb.events*).
Prediction
An AI model training process that includes data selecting, data cleaning, starting and stopping training, pipeline viewing and publishing,
model testing, workload snapshot optimizing, and more.

Tuning IBM Cloud Pak for Data model training parameters

The following model training parameters are found in the lsf_cognitive_v1/conﬁg/conﬁg.json ﬁle:
"enabled":true|false
If false, prediction feature is disabled.
"sample_rate":1
Sub-sample rate. A value of 0.5 means that 1/0.5 = 2 jobs are handled to produce 1 record. To handle large amounts of data with 10
million jobs, the value must be smaller, such as 0.01.
"max_samples": 2000000

Deploying models to IBM Spectrum LSF production environment
You can deploy your trained model to your LSF production environment.
About this task
When you publish a pipeline as a model, an esub script is generated. The esub script calls the LSF Predictor REST API to do inference, then applies
the predicted max_mem and run time values in the job’s resource requirement rusage string and estimated run time parameters during the job
submission. The esub script is responsible for doing the following items for a newly submitted job in the LSF production environment:
Organizing the required model input data.
Calling the LSF Predictor REST API to get predicted values.
Replacing the memory value in the job resource requirement rusage string or the value of the estimated run time with the predicted one.
Procedure
1. Download the esub script.
After publishing your model pipeline found under the Pipelines tab, you can download the esub script by clicking the Esub action.
2. Optional: Modify the contents of the esub script if you have some customized requirements.
3. Log in to the LSF server host as root.
